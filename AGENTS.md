## Product operating record checkpoints

Read [the operating checklist](docs/operating-record/checklist.md) at the start of each milestone. Apply [the adopted standard](docs/product-operating-record-standard.md): C0 intake, C1 design, C2 implementation, C3 pre-release, C4 post-release evidence, C5 maintenance/handoff. Update affected diagrams, inventory, runbooks and owned gaps in the same PR; copy `docs/operating-record/reports/TEMPLATE.md` for a dated report and record ship/revise/hold for the named scope. Preserve previous reports. A generated or documented procedure is not verified behavior. Distinguish default source, unmerged candidate work, intended configuration and observed deployment. Never infer provider state, recovery success, costs or human approval; keep unknowns explicit. No checkpoint itself authorizes provider mutation or deployment.
